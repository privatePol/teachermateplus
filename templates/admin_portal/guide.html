1. Quick Start Sequence

Phase A - Foundation Setup
  1. Set top scope first: Tenant then Campus.
  2. Verify academic setup: AY/Term, Course, Section, Offering, Faculty Assignment.
  3. Set active AY/Term for faculty active/archive behavior.
Phase B - Governance Controls
  1. Configure grading deadlines and lock rules.
  2. Set correction governance mode and route matrix.
Phase C - Operations Monitoring
  1. Monitor submissions, reopen actions, and correction queue.
  2. Run audit checks before official release/export.
Recommended sequence each term: Scope -> Setup -> Governance -> Monitoring. Avoid doing reopen/correction actions until deadline rules and correction mode are already configured.

2. Scope Selectors (Tenant/Campus)

  • Tenant/Campus selectors define operational scope for most list/create/edit actions.
  • Wrong scope selection causes missing/incorrect records in view.
  • Always verify scope before import, reopening, and policy updates.
How To
  1. Select tenant first, then select campus.
  2. Open target module and verify listed records align with selected scope.
  3. If data looks wrong, check selectors first before deeper troubleshooting.

3. Configuration Setup

What To Set Up
Setup Area Where To Apply Purpose
Tenants and Campuses Admin Portal -> Organization -> Tenants / Campuses Create the institutional scope first so all later academic and governance records attach to the correct tenant and campus.
Departments and Programs Admin Portal -> Organization -> Departments / Programs Set the academic structure that will be used for courses, sections, faculty scoping, and approval routing.
Academic Years and Terms Admin Portal -> Academics -> Academic Years / Terms Define the academic calendar used by offerings, enrollment, grading, and submission governance. Mark each term as Regular, Summer, or Special so term-type grading profiles can resolve the correct final-grade rule.
Courses and Sections Admin Portal -> Academics -> Courses / Sections Create the academic masters that will later be paired into actual class offerings.
Course Offerings Admin Portal -> Academics -> Course Offerings Open the actual class records for the selected Academic Year, Term, Course, and Section.
Faculty Assignments Admin Portal -> Academics -> Faculty Assignments Assign the faculty members who will handle each offering in the Faculty Portal.
Course Template Assignment Admin Portal -> Grading -> Course Template Assignments Assign the correct grading template to course masters. Bulk assignment can now be used when many courses share the same template.
Tenant Grading Profiles Admin Portal -> Grading -> Tenant Grading Profiles Configure profile scope, template, passing threshold, and final-grade formula. Leave Applicable Term Type blank for all terms, or choose Summer/Special when a different reusable formula should apply to that term type.
Template Coverage Check Admin Portal -> Grading -> Course Template Assignments Use the metric cards and the Courses with no grading template filter to identify courses that still need template coverage.
Enrollment and Grading Readiness Admin Portal -> Enrollment and Admin Portal -> Grading Proceed only after the setup chain above is complete and the needed grading template coverage is already in place.
How To
  1. Follow the setup order strictly: Tenant -> Campus -> Department/Program -> Academic Year/Term.
  2. Create course and section masters first, then create the actual course offerings.
  3. Assign faculty only after the offering is already complete and properly scoped.
  4. Go to Course Template Assignments after offerings are ready so every course has grading-template coverage before operations begin.
  5. When many courses share one template, use the bulk assignment screen and let EduGradesPro skip courses that already have a prior assignment in the same term scope.
  6. Before moving to enrollment, imports, or grading operations, verify that all referenced setup records are active and that no needed course is left without a grading template.
Recommended build order: complete organization and academic masters first, then open offerings, then assign faculty, then verify grading-template coverage, and only after that proceed to enrollment and live grading operations.

3A. Grading Template Testing Calculator

  • Use the calculator to validate how EduGradesPro will compute a grading template before live use.
  • The calculator is read-only and uses sample raw score and total score values only. It does not create grades, activities, or student records.
  • Testing inputs are accepted at the lowest active level of the selected template: detail if present, otherwise subcomponent, otherwise component.
  • The page now uses a simpler builder-style presentation first, such as PRELIM GRADE = Prelim Exam (40%) + Class Standing (60%), before showing the actual computed values.
  • This is the best place to explain to operations or deans how a template produces Prelim, Midterm, Pre-Final, Final Exam, and Final Grade outputs.
How To
  1. Open Grading Templates then click Test Calculator for the target template.
  2. Confirm the default sample raw score or replace it with the sample value you want to use.
  3. Review each period block and adjust raw score / total score rows where you want different test values.
  4. Click Load / Recompute Calculator.
  5. Review the period formula, the simple class-standing hierarchy, then the computed results per period.
Important: the calculator validates template weighting and period/final-grade computation. It does not replace actual grade entry and it does not simulate activity totals or raw-score encoding behavior.

4. Records Management

  • Use filters before editing records.
  • Prefer inactivation for historical traceability.
  • Keep codes consistent across imports and operations.
  • Review related dependencies before major edits.
How To
  1. Filter -> Edit exact record -> Save -> Re-verify in list.
  2. Inactivate records instead of deleting when operations already depend on them.
  3. In Admin Portal -> Enrollment, use the status summary cards to quickly review how many rows are currently ACTIVE, DRP, W, or INC inside the current filtered scope.
Data quality is the top source of grading stability.

5. Governance Settings

What To Configure
Governance Area Where To Apply What To Set
Active Academic Scope Admin Portal -> Tools -> Active Academic Scope Set the active Academic Year and Term so faculty classes route correctly between active and archived views.
Active Grading Period Admin Portal -> Tools -> Active Grading Period Define the canonical period catalog for the selected term, choose the active period per campus, decide whether EduGradesPro should auto-advance after the current active period deadline, and control which faculty period card stays open for normal work. Auto-advance moves forward only; changing a deadline afterward does not move the active period backward.
Correction Governance Admin Portal -> Tools -> Correction Governance Choose SYSTEM_REQUEST or MANUAL_ONLY, then set pre-deadline behavior and approval routing by faculty department.
Grading Template Governance Admin Portal -> Tools -> Template Governance Assign who can draft, submit, review, approve, publish, request hotfix, and apply hotfix for grading templates.
Sequential Template/Hotfix Chain Admin Portal -> Tools -> Template Governance Turn on the Phase 2 workflow if you want step-by-step review such as Template Review -> Final Approval and Hotfix Review -> Hotfix Final Apply.
Document Print Settings Admin Portal -> Tools -> Document Print Settings Set official print header values and document identity details for reports and exported forms.
Optional Workflow Features Admin Portal -> Tools -> Configuration Management Turn optional features on/off such as official correction PDF, registrar auto-email, assignment-primary default behavior, class master list ownership mode and Faculty DRP cutoff for roster maintenance, grade prediction options, login security, and the official-grade release restriction that can delay computed period grades and final grades until after deadline.
Tenant Grading Formula Admin Portal -> Grading -> Tenant Grading Profiles Define the matched grading template, passing threshold override, and final-grade formula for a tenant scope. Default mode averages all active template periods; weighted mode lets you declare specific period weights per tenant/campus/department/program/course scope. If the profile leaves passing threshold blank, EduGradesPro now falls back to the grading template threshold before using the tenant default.
How To
  1. Select the correct Tenant and Campus first from the top scope selectors.
  2. Open the matching settings page under Tools based on the governance area you are adjusting.
  3. Before configuring deadline auto-locks, make sure the selected term already has the correct canonical grading periods and an active period set for the campus.
  4. For grading templates, start with Template Governance and assign the allowed roles before delegating any template work.
  5. If you need stricter control, enable the sequential workflow chain and separate review roles from final approval/apply roles.
  6. Save the settings, then verify the affected behavior in template screens, correction screens, and faculty flows.
  7. Limit update permissions to only the governance roles that should manage policy.
Recommended NCBA starting point: keep template drafting, submission, and hotfix request under the steward role; turn on sequential workflow; use Dean/AC for the review step; and keep final approval, publishing, and hotfix final apply under CAO governance.

6. Tools and CSV Importing

Import Areas
Import Type Where To Apply Use Case
Sections Admin Portal -> Tools -> Bulk Imports Load section masters in bulk when many section records need to be prepared at once.
Courses Admin Portal -> Tools -> Bulk Imports Load course masters in bulk using the required EduGradesPro template structure.
Course Offerings Admin Portal -> Tools -> Bulk Imports Create the actual offered classes for a term by importing prepared offering rows.
Faculty Assignments Admin Portal -> Tools -> Bulk Imports Assign faculty to offerings in bulk after offerings are already in place.
Enrollment Admin Portal -> Tools -> Bulk Imports Load students into offerings in bulk after academic setup and class offerings are ready.
Import Monitoring Admin Portal -> Tools -> Bulk Imports Review validation results, row-level errors, duplicate checks, and the final confirmation state before inserting data.
How To
  1. Open Admin Portal -> Tools -> Bulk Imports and choose the import type you need.
  2. Download and use only the system-generated CSV template for that import type.
  3. Populate the CSV using valid business keys such as codes, usernames, and tenant/campus values expected by EduGradesPro.
  4. Upload the CSV and review the validation result first. No insert should happen yet during this stage.
  5. Review row-level errors, duplicate warnings, and unresolved references before confirming.
  6. Fix the source file, re-upload if needed, then confirm only when the preview is clean.
  7. After confirmation, verify the target list page so the imported records appear in the correct scope.
Strict headers are required by design; custom formats are rejected.
Recommended import order: sections and courses first, then course offerings, then faculty assignments, and only after those are ready should enrollment imports be processed.

7. Submission and Reopen Control

Control Area Where To Apply What To Monitor / Action
Grading Period Locks Admin Portal -> Grading -> Period Locks Set the submission deadline, active rule state, open/locked behavior, and coverage per campus, term, period, or specific course offering.
Non-Compliance Monitor Admin Portal -> Grading -> Non-Compliance on Periodic Grades Submission Track overdue class-period rows after deadline. Unsubmitted gradebooks remain open for faculty encoding, while authorized academic users monitor non-compliance and missing-record readiness here.
Grade Submission Status Admin Portal -> Grading -> Grade Submissions Track which class-period rows are still open, already submitted, reopened, or still waiting for faculty action.
Reopen Governance Admin Portal -> Grading -> Grade Submissions plus Admin Portal -> Tools -> Correction Governance Use reopen controls only when the required governance basis already exists, such as approved system workflow or an authorized manual approval.
Deadline Automation Admin Portal -> Grading -> Period Locks and scheduled operations Back deadline-based controls with the scheduled auto-lock process so the open window closes consistently even if staff do not manually revisit the page.
Faculty Re-Submission Faculty Portal -> My Classes after admin reopen After a class-period is reopened, faculty must finish the approved correction and submit the class again before the allowed closing time.
How To
  1. Create the needed Period Lock row first, with the correct campus, term, and the actual grading period code used by the template plus the intended deadline.
  2. Use Scope Type: Campus when one deadline/lock applies to all classes in the selected campus, term, and period. Use Scope Type: Course Offering only when one class needs a different rule; the course-offering rule takes priority for that class.
  3. Use Is locked only when faculty editing should be disabled for that scope. Leave it unchecked when the rule is only a deadline/reminder/compliance checkpoint.
  4. Use Is active to enable or disable the rule. Inactive rules stay available for review but are ignored by faculty pages, deadline checks, and scheduled auto-lock processing.
  5. Use Grade Submissions to monitor open classes as the deadline approaches and follow up on rows that are still pending.
  6. After deadline, use Non-Compliance on Periodic Grades Submission to see accepted faculty assignments that still have overdue unsubmitted grade books for each grading period.
  7. Unsubmitted overdue grade books remain open until the faculty submits them. The deadline acts as a compliance checkpoint, not an automatic encoding shutdown.
  8. Use correction workflow only for already submitted grade books that need changes. Do not use deadline policy to force reopen for unfinished but unsubmitted encoding.
Reopening a Submitted Class (Admin Procedure)
  1. Open Grade Submissions and filter by campus/term/course/section/period.
  2. Confirm approved basis (system request approval or manual signed form).
  3. Click Reopen for the exact class-period row.
  4. Confirm the row status changes from SUBMITTED to open/reopened state.
  5. Inform faculty to apply corrections and re-submit before deadline.
Reopen always applies to the exact class-period submission record. Verify the campus, term, course, section, and period carefully before clicking so you do not reopen the wrong teaching load.

8. Grade Correction Process (System vs Manual)

Correction Path Where To Apply What To Do
System Request Mode Faculty Portal -> Grade Correction and the configured approval route Faculty files the request online, approvers review by route matrix, and final approval posts the corrected values directly into the gradebook.
Official PDF Artifact Admin Portal -> Grade Correction Requests after approval Open the approved request as an official PDF for registrar/AIMS reference, print/download, and evidence retention when the feature is enabled.
Approval Notifications Correction Governance and notification settings Send NCBA-branded notification cards to approver roles such as CAO and Dean when request submission notifications are enabled.
Manual Only Mode Paper form + Admin Portal reopen path Use the paper route when policy requires it; after approval, authorized admin reopens the exact class-period so faculty can apply the correction and re-submit.
System Request Mode
  1. Faculty files the correction request in the portal.
  2. Approvers review it based on the configured route matrix and permissions.
  3. Faculty may include multiple students or the entire class plus multiple grading items in one request.
  4. Original values are shown in the request, and faculty enters only the corrected values.
  5. Final approval applies the corrected values directly into the gradebook and recomputes the affected student period and final grade automatically.
  6. No additional faculty finalize step is required for this direct score-correction petition flow.
  7. If the configurable feature is enabled, approved requests can also open as an official PDF artifact in a new browser tab for registrar/AIMS reference and immediate print/download, including campus applicability, before/after official grade values, and approval summary directly above registrar reference.
  8. If the configurable feature is enabled, submission of a correction request can immediately email the selected approver roles such as CAO and college dean, using the NCBA-branded notification card with petitioner and period name details.
Manual Only Mode
  1. Faculty files the paper correction form.
  2. Manual approvals are completed outside the system.
  3. After final paper approval, authorized admin reopens the class-period in EduGradesPro.
  4. Faculty applies the approved correction and re-submits grades.
Important Guardrails
  • The route matrix is based on the requesting faculty department.
  • CAO, dean, and coordinator users must have the correct scoped roles.
  • Use remarks and reference numbers for traceability, especially in manual mode.
  • All correction and reopen decisions are auditable.
  • Approved score correction values should be reviewed carefully because the final approval posts them directly into the gradebook and records before/after score, period-grade, and final-grade audit entries.
If registrar policy requires paper source-of-truth, set mode to MANUAL_ONLY. Faculty does not file online request; admin executes reopen only after approved form.

9. Security and User Administration

User Account Security
Security Control What It Does Where To Apply / Review
Password Complexity Validation Prevents weak passwords during account setup and password reset/change flows. Admin Portal -> Security -> Users and account password-change flows.
Forced Password Change Requires users to replace the issued password before entering the portal after first sign-in or reset. Applied automatically by the account security flow after user creation and password reset.
Privacy Consent Flow Requires users to review and accept the current EduGradesPro Privacy Consent before using the portal. Shown automatically at login when consent has not yet been recorded for the current version.
Single-Device Session Enforcement Revokes older active sessions for the same user when they sign in on a new device or browser. Applied automatically on successful sign-in for protected portals.
Session Timeout Ends inactive portal sessions after 1 hour so stale browser sessions do not stay open too long. Applied automatically through Django session settings for both Admin Portal and Faculty Portal.
Email Login OTP Requires a one-time code sent to the user's registered email after the password is accepted. Admin Portal -> Tools -> Configuration Management -> Login Security controls enablement and OTP expiry minutes.
Temporary Login Lockout Temporarily blocks repeated failed login attempts to reduce password-guessing and brute-force abuse. Admin Portal -> Tools -> Configuration Management -> Login Security for policy, and Admin Portal -> Security -> Login Lockouts for monitoring and manual unlock.
Scheduled Faculty Deactivation Lets an authorized admin set a future date/time when a faculty account should become inactive. The scheduled job applies the deactivation and clears active sessions. Admin Portal -> Security -> Faculty Deactivation; schedule manage.py apply_scheduled_user_deactivations in cron.
Admin Rules
  • Assign default tenant, campus, and department correctly per user before giving portal access.
  • Grant least privilege and role scopes carefully. Role assignments can now be scoped by tenant, campus, and department for AC/Dean governance boundaries.
  • For dual-role users (admin + faculty), ensure both portal permissions are assigned.
  • Use scheduled faculty deactivation when a faculty account should remain active until a specific separation, clearance, or end-of-load date.
  • If email OTP is enabled, every protected sign-in requires the user's registered email to be present and reachable.
  • Recommended login lockout baseline: 5 failed attempts within 15 minutes, with a 15-minute lockout.

10. Faculty Assignment Acceptance and Monitoring

Workflow Summary
  • Newly assigned classes remain pending until the faculty member acknowledges the load.
  • Pending assignments block access to grading and class-list work.
  • Faculty may accept, request clarification, or decline with a written note.
  • Pending assignments carry a response deadline and may expire if left unanswered.
  • Expired assignments require admin refresh before the faculty member can respond again.
Admin Procedure
  1. Open Faculty Assignments and select the faculty member.
  2. Assign the offering and include instructions when needed.
  3. By default, EduGradesPro can mark new faculty assignments as primary. If that tenant setting is turned off, use the Set Primary button manually for the lead load.
  4. Monitor the load status for Pending, Accepted, Clarification Requested, Declined, or Expired.
  5. Use the metric cards to watch Accepted, Pending Acceptance, Due Within 24 Hours, and Expired.
  6. Review clarification or decline notes before editing or reissuing the assignment.
  7. If the assignment expired, refresh or reissue the load so a new response window is created.
Admin Rules
  • Do not treat a class as ready for grading until the assignment is accepted.
  • Use assignment instructions for schedule notes, room clarifications, or load-specific guidance.
  • Reissuing or changing the load should reset the acknowledgment window so the faculty confirms the latest version.
  • Follow up quickly on items marked Due Within 24 Hours.
  • Schedule manage.py process_faculty_assignment_reminders so reminders and expirations run automatically.
This workflow creates a formal checkpoint between load assignment and grading access, helping protect both faculty accountability and class-start readiness.

11. Audit and Monitoring

  • Use dashboard and analytics to monitor submissions, failures, and exceptions.
  • Use audit logs for policy-critical actions and decision traceability.
  • Review correction/reopen actions before official release.
  • Use Faculty Activity Monitor to identify faculty who have not logged in, created activities, or encoded grades within the selected weekly or term window.
  • Use Faculty Grade Book Monitor for read-only academic oversight of a scoped faculty member's classes and period grades.
Faculty Activity Monitoring
  1. Open Faculty Activity Monitor from the Dashboard quick actions or from the Faculty Assignments page.
  2. Filter by campus, department, and term so AC and CAO review only the teaching loads they are responsible for.
  3. Choose the monitoring window, such as Last 7 Days or Current Term, to match the follow-up cycle you want.
  4. Review the summary cards first for No Login, No Activity Created, and No Grade Encoding counts.
  5. Use the new Window Activity Trend section to see whether logins, activity creation, score encoding, and gradebook work are sustained across the selected weekly or term view.
  6. Use the faculty table to spot who still has classes with No Activity Yet or No Scores Yet.
  7. Review the row-level flag badges to identify faculty who need follow-up for No Login, No Gradebook Update, or missing class maintenance.
  8. Open the optional faculty drilldown when you need the class-by-class view and recent auditable actions before contacting the faculty member.
  9. Inside the selected faculty drilldown, use the new Week-over-Week Comparison charts to compare six weekly slices of login, activity setup, score encoding, and gradebook work for one faculty member.
  10. Use Print Report when you need a clean monitoring snapshot for meetings, weekly review, or compliance follow-up.
This monitor is designed for academic follow-up. It helps AC and CAO see whether faculty are actively maintaining gradebooks before deadline pressure becomes a larger governance issue.
Faculty Grade Book Monitoring
  1. Open Faculty Assignments and select the faculty member within your allowed tenant, campus, and department scope.
  2. Use the acceptance status and metric cards to confirm whether the faculty member already acknowledged the assigned load.
  3. Watch the Due Within 24 Hours and Expired metric cards so pending loads do not stall class opening and grading start-up.
  4. Review any assignment instructions, clarification requests, or decline notes directly on the assigned-offerings table before changing the load.
  5. Click Open Grade Book, then choose the class and grading period to review.
  6. Review the metric cards first for class coverage, averages, and pass rate before drilling into detailed rows.
  7. Use the student search box when you need to isolate a specific record during review.
AC, Dean, and CAO monitoring opens the grade book in read-only mode. Student identity can be masked by role, and every monitor open is recorded in the audit trail.
Operations tip: schedule manage.py process_faculty_assignment_reminders in cron so pending loads are reminded automatically and overdue loads are marked expired without waiting for a user to open the page.
Grade Prediction Monitor
  • Prediction is unofficial and read-only. It must be enabled first in Configuration Management.
  • Open Grade Prediction Monitor to review projected outcomes for the scoped faculty, class, and period.
  • Use the monitor to spot low coverage, at-risk students, and likely current-period outcomes before submission deadlines.
  • Operational timing: Prelim is early warning, Midterm is the strongest intervention window, Pre-Final is the last follow-up checkpoint, and Final is mostly confirmation.
  • Faculty-side at-risk monitoring focuses on the active grading period when one is configured, while detailed final-grade projection remains available on the prediction detail page.
  • Prediction uses the same grading template path as the official computation engine, but it never writes to the gradebook.
  • Refresh the prediction snapshot after major score changes when you need an updated projection immediately.
Faculty Grade Distribution Monitor
  1. Grant authorized academic leaders the grade_distribution_monitor.read permission through Roles or direct user permissions.
  2. Open Configuration Management, then set the Faculty Grade Distribution Monitor thresholds for high-grade bands, exact 100 rates, low variation, and small sample size.
  3. Open Grade Distribution Monitor from the Admin Dashboard quick actions or the Grading menu.
  4. Filter by tenant scope, campus, department, academic year, term, faculty, course, class, period, component, or sub-component as needed.
  5. Use Period Grades to review official stored period-grade distribution, or Activity Scores to review encoded activity-score patterns.
  6. Review the neutral status badges: High Grade Concentration, High Perfect Score Rate, Low Grade Variation, Small Sample, and Incomplete Data.
  7. Use Export CSV when a meeting or review needs an aggregated copy of the scoped results.
This monitor is read-only and uses aggregated data by default. It is intended for academic review and informed follow-up, not automatic disciplinary action.
Submission Non-Compliance Notices
  1. Open Configuration Management, then find the Submission Non-Compliance Notices card.
  2. Enable the feature, set the repeat interval in days, select the academic-head roles that should be included in the visibility/escalation chain, and enter the HR escalation email recipients.
  3. Use scoped role assignments for academic heads such as AC, Dean, or CAO so each user sees only the overdue classes inside the correct tenant, campus, and department scope.
  4. Open the Non-Compliance on Periodic Grades Submission report to monitor overdue unsubmitted classes and review the latest notice stage and issue date.
  5. Remember the cadence: first communication is Notice for Non-Compliance, second is Warning for Continued Non-Compliance, and third onward is Escalation for Unresolved Non-Compliance until the affected grading period is submitted.
Best practice is to run the notice scheduler daily, not every three days. EduGradesPro checks the configured repeat interval and only issues a new communication when the next stage is actually due.
Scheduled job command: manage.py issue_submission_non_compliance_notices
Optional dry run: manage.py issue_submission_non_compliance_notices --dry-run
Optional tenant scope: manage.py issue_submission_non_compliance_notices --tenant-id 1
Operations tip: schedule this command as a daily background task on the application server after SMTP/email settings are confirmed. The command only issues read-only communications and does not lock classes or change any grade records.

12. End-of-Term Checklist

  • Confirm active AY/Term and role scopes.
  • Confirm all lock/deadline configurations are correct.
  • Track and resolve non-submitted classes.
  • Process correction/reopen according to chosen policy mode.
  • Open Faculty Final Clearance once final submissions are complete to preview which assigned classes are already complete or still incomplete per faculty member, and to verify already generated official clearance reports.
  • Faculty generates the official clearance in the Faculty Portal. Authorized personnel may verify a printed copy either by scanning the printed QR code or by entering the printed Reference No. and Verification Code in the Admin Portal verification lookup.
  • Configuration Management now includes a User Signatures card so NCBA can decide whether encrypted account signatures are allowed at all, and whether they may appear on Faculty Final Clearance and Correction Official Report PDFs.
  • Sensitive correction attachments and official correction reports open through authenticated EduGradesPro views and are recorded in audit logs. IT must still ensure protected media folders are not directly exposed by the production web server.
  • Review audit logs and analytics before final release/export.

14. Production Incident Response

Incident Step What To Do Where To Apply / Check
1. Capture Evidence Get the exact URL, timestamp, screenshot, affected role, and the last successful action before the error. Browser error page, user report, and server timestamp reference.
2. Confirm Scope Check whether the issue affects Admin Portal, Faculty Portal, one campus, one tenant, or only a single page. Admin and Faculty login pages, dashboard pages, and one affected workflow page.
3. Freeze Risky Changes Avoid random redeploys, direct database edits, or repeated retries while the root cause is still unknown. Operational response discipline during live incident handling.
4. Check Server Health Review gunicorn, nginx, EduGradesPro logs, disk space, and recent release state first. Production server logs and the Ubuntu deployment environment.
5. Decide Recovery Path Choose rollback if the outage came from a fresh deploy and the previous release was stable. Choose a hotfix if the root cause is clear and isolated. Release history, recent deployment notes, and current impact scope.
6. Escalate with Evidence Send traceback, screenshot, URL, affected user/role, and recent change context so a safe patch can be prepared quickly. docs/PRODUCTION_INCIDENT_RUNBOOK.md and incident support coordination.
Where To Apply
  1. Use the detailed production response guide in docs/PRODUCTION_INCIDENT_RUNBOOK.md for command-level triage and rollback/hotfix decisions.
  2. Use Admin Portal -> Security -> Login Lockouts if login failures or account lockouts are part of the incident.
  3. Use Admin Portal -> Audit Logs and governance pages when the incident involves template, correction, reopen, or scope-setting changes.
  4. Use the production deployment guide in docs/DEPLOYMENT_UBUNTU.md for service restart and release-update procedures.
Practical rule: during a production incident, preserve evidence first, stabilize second, and only then deploy a rollback or hotfix. Do not guess directly in the live database.
