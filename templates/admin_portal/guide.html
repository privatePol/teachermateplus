1. Quick Start

Follow this order when preparing a new term.

A. Basic Setup
  1. Choose the correct Tenant and Campus.
  2. Check the Academic Year, Term, Courses, Sections, Offerings, and Faculty Assignments.
  3. Set the active Academic Year and Term.
B. Rules
  1. Set grading deadlines and lock rules.
  2. Set the correction rule and approval route.
C. Monitoring
  1. Watch grade submissions, reopen requests, and correction requests.
  2. Check audit logs before official release or export.
Best order each term: Scope -> Setup -> Rules -> Monitoring. Set the rules first before handling reopen or correction requests.

2. Scope Selectors

Always choose the correct tenant and campus before working.

  • The Tenant and Campus selectors control what records you can see and edit.
  • If the wrong scope is selected, records may look missing or incorrect.
  • Check the scope before importing, reopening, or changing rules.
How To
  1. Select the tenant first.
  2. Select the campus next.
  3. Open the page you need and check if the records match your selected scope.
  4. If the records look wrong, check the selectors first.

  1. Follow this order: Tenant -> Campus -> Department/Program -> Academic Year/Term.

  3. Assign faculty only after the offering is already complete and properly scoped.

  6. Before enrollment, use the offering coverage filter to confirm that every current offering has an active published exact-term or default course-template assignment.
Recommended build order: Finish organization and academic records first. Then create offerings, assign faculty, check templates, and proceed to enrollment.

3A. Grading Template Testing Calculator

Test a grading template before using it in live classes.

  • Use the calculator to check how a grading template computes grades.
  • It is read-only. It uses sample scores only and does not save student grades.
  • The calculator uses the lowest active level of the template: detail, subcomponent, or component.
  • For subcomponents with detail rows, choose Weighted Details when detail weights must apply, or Average Activities when faculty-created activities under those details should count equally.
  • It shows simple formulas first, then the computed values.
  • It also shows the final-grade rule from the matching Tenant Grading Profile.
How To
  1. Open Grading Templates, then click Test Calculator.
  2. Use the sample scores or enter your own sample values.
  3. Click Load / Recompute Calculator.
  4. Review the period formula, period result, and final-grade calculation.
Important: this is only a test tool. Faculty still encode actual scores in the Faculty Portal.

4. Records Management

Keep school records clean and easy to trace.

  • Use filters before editing records.
  • Inactivate old records instead of deleting them.
  • Keep codes consistent across imports and operations.
  • Check related records before making large changes.
  • Use Enrollment -> Student Enrollment Query when an authorized admin needs to check one student's consolidated enrollment and grade records for a selected Academic Year and Term.
How To
  1. Filter -> Edit exact record -> Save -> Re-verify in list.
  2. Inactivate records instead of deleting when operations already depend on them.
  3. In Admin Portal -> Enrollment, use the status summary cards to quickly review how many rows are currently ACTIVE, DRP, W, or INC inside the current filtered scope.
  4. For one-student checking, open Admin Portal -> Enrollment -> Student Enrollment Query, search the student, select the Academic Year and Term, then review the enrollment and grade details shown on the page.
Departmental Exam Builder: Create the cycle from Overview / Exam Cycles, then use Assigned Course Examinations -> Administer. One grouped examination is shared across all listed campuses where the course is offered, including Cubao, Fairview, and Taytay where applicable; it is not one examination per campus. One responsible exam department owns that grouped examination across those campuses, not separately per campus. The Responsible Exam Department selector shows the campus with every Department, so records with the same code and name remain distinguishable; select one, save responsibility, and reload before choosing a reviewer for that exact Department. New cycle courses start Included. For Manual Review, use Exempt and Restore to Included only while the cycle is Draft. Automatic Generation also permits an Included course to become Exempt while its cycle is Open when no current generated revision exists; the saved exam configuration is preserved, as is all contribution/question/import history, while processing becomes dormant. Saved configuration alone does not block Exempt; Faculty contribution or question work blocks choosing Exempt. An Exempt Automatic course can be restored during that same Open cycle only before its existing effective contribution deadline. Restore does not use the Exempt-only contribution/question blocker, ask for a new deadline, or substitute the cycle default; a missing, reached, or passed deadline, or a current generated revision, blocks the operation without mutation. Successful Restore reopens the configuration with both stored deadline fields unchanged, resets Automatic processing, initializes the contributor roster when it has never been initialized and otherwise synchronizes the current roster, preserves Draft/Submitted contributions and questions, and revalidates the reviewer (an ineligible reviewer may be cleared). No downstream data is deleted. Use PRINT ALL for the complete authorized, course-code-sorted listing with cycle, responsibility, configuration, inclusion, and readiness context but no action controls. Use Print Exempt Courses for the authoritative Exempt-only reconciliation list with category and reason. Neither report changes course or exemption state. Reviewers see exempt assignments as read-only. For current Stage 4 readiness, authorized managers set independent 50-75 count defaults, a cycle-wide contribution deadline, and contributor instructions, then review the signed Apply defaults confirmation. Authorized course configurators inherit defaults or set intentional exceptions. Effective values are labeled DEFAULT, OVERRIDE, or NOT CONFIGURED; removing a deadline override restores the cycle deadline or NOT CONFIGURED when no cycle deadline exists. The Draft/Open/Closed readiness controls preserve the first-open historical snapshot, while a Closed governing cycle hides and denies configuration/default mutations. They do not provide faculty contribution, question-bank, official questionnaire, answer-key, generation, review/approval, PDF, or export actions.
Word question import: In Tools -> Configurable Features, Word (.docx) Question Import is a separate tenant setting and defaults Off. Enable it only when Faculty should receive the bounded Upload, Review & Fix, and Import workflow inside an authorized Draft Question Bank. It accepts standard macro-free .docx only and does not provide antivirus protection; Word, LibreOffice, macros, and external resources are never invoked.
Planning & Readiness: Authorized users can review live active/open offerings grouped only by Course.exam_department, with course and overall enrollment, assignment-acceptance, Faculty-role, and TMP account-readiness totals. Every choice, row, and total stays inside the exact tenant/campus/Exam Department scope assigned with departmental_exams.view_planning_readiness; unassigned Exam Department courses appear only for global department scope on that exact campus. The page is read-only. Its printer-friendly view additionally requires departmental_exams.print_planning_readiness, and print permission alone grants no report access.
Automatic Generation: Use Automatic Generation Summary for generated and blocked courses. The scheduled deadline processor isolates each grouped examination in its own time-bounded process, so one pathological course cannot prevent later courses from being processed. A timeout is shown as Automatic generation exceeded the per-course processing time limit and requires administrator review; that Closed terminal result is not retried until an authorized Reopen Contributions or eligible Restore resets processing. On Questionnaire Print Release, confirm the exact revision and bounded Asia/Manila Print From/Print Until window. Faculty see separate Set A and Set B actions only for that released revision inside the window; regeneration does not release the newer revision automatically. Bulk Print Release selects one exact revision per course and applies one common window in an all-or-nothing batch, while every course retains its own independent release record and replacement history. Admin Direct Print opens sanitized Print Set A or Print Set B without creating or changing a Faculty release. Faculty and Admin questionnaire print pages default to Letter paper and also support A4 and Legal; choose the paper size before opening the browser print dialog. Supported scientific notation in Question Text and Choices A-D renders from escaped immutable snapshots, and the Print action waits for initial notation rendering and available browser fonts.

Confidential review and separate Faculty Answer Key release: Authorized reviewers may open exact-revision Set A and Set B Answer Keys and the Question Selection Audit. An Admin with the separately assigned departmental_exams.release_answer_keys permission may release the exact current-final Answer Key to currently assigned Faculty only after confirming that all examination sessions concluded and setting an independent Available From/Until window. Questionnaire release never grants Answer Key access. Supersession blocks the older release immediately, and the newer revision requires explicit release. Audit summaries show Submitted Questions, Unique Logical, Duplicate/Equivalent Copies, Set A, Set B, Overlap, Selected Unique, and Not Selected. Rows show No., Question, Contributor, Campus / Context, Difficulty, Correct Answer, Source (Q### r#), Set A position, Set B position, and Equivalence Status. Status is Unique, Selected representative (EQ-###), Equivalent copy not selected (EQ-###), or Unselected equivalent group (EQ-###); EQ-### is an audit-friendly equivalence-group label, not a raw hash. Recommended fast review: Summary -> Selected in Both -> Duplicate/Equivalent -> Not Selected.

Automatic Generation Audit: PASS means every available deterministic check passed; WARNING means a check could not be completed, commonly because an older legacy revision did not persist full historical source evidence; FAIL means a deterministic mismatch was found. These are revision-bound checks, not AI judgment. Newly generated revisions retain the full source-audit evidence. Answer keys and audit reports remain confidential and are never provided through Faculty questionnaire printing.
Contributor Completion: Use the cycle, period, course, and contributor filters to narrow the already authorized monitoring scope. Submitted rows are green and show their Date Submitted; Draft rows show an em dash for that date. An Exempt course is marked with a warning badge and has no Initialize/Synchronize roster action. The printer-friendly view keeps the same active filters and its four columns: Contributor, Campus, Section, and Progress.

Automatic Generation Readiness: Authorized Automatic managers can open the separate readiness action and select one authorized Automatic cycle. Screen and print share seven management columns: sequential No., Authorized Course, Campuses Offered, narrow Final Exam Items, Contribution Progress, Automatic Exam Generation Status, and bulleted Action Needed. Filtered rows restart at No. 1, and the shared Report Summary counts only rendered authorized rows by their existing displayed status. Contribution Progress compares Submitted question volume with the effective configured quota multiplied by distinct offered campuses; it is monitoring only and may exceed the technical generation minimum. A roster that has not been initialized directs the manager to Initialize; only an initialized roster whose eligible Faculty list changed directs the manager to Synchronize. The report performs usable unique-question, 30/50/20 difficulty, campus-policy, and aggregate shortage checks, but it does not run the exact Set A/B solver. Aggregate-sufficient rows are labeled EXACT FEASIBILITY PENDING; authoritative generation still applies overlap and exact Set A/B feasibility before creating sets. Missing campuses use concise action bullets; AVAILABLE WITH WARNING may still proceed from a sufficient represented-campus pool, while STRICT remains blocking. The report never starts generation and never displays question text, choices, answers, fingerprints, or source identifiers.
Clean records help prevent grading problems.

Active Grading Period Admin Portal -> Tools -> Active Grading Period Load the term period catalog once for the tenant and term, then set the active grading period for each campus. This controls the normal period focus in the Faculty Portal.

How To
  1. Select the correct Tenant and Campus first from the top scope selectors.
  2. Open the correct settings page under Tools.
  3. Before deadline locks, make sure the term has the correct grading periods.
  4. For grading templates, set the allowed roles before assigning template work.
  5. Use the step-by-step workflow when review and final approval need different users.
  6. Save the settings, then check the affected faculty and admin screens.
  7. Give update permissions only to users who should manage policy.
How To Configure Active Grading Period Per Campus
  1. Open Tools -> Active Grading Period.
  2. Select the first campus, for example Fairview.
  3. Select the term, for example 2nd Semester - AY 2025-2026.
  4. Click Load Scope.
  5. If the term period catalog has no active rows, click Load Standard 4-Period Set. This creates or reactivates Prelim, Midterm, Pre-Final, and Final for the selected term.
  6. In Set Active Period, choose the period that is active now for that campus.
  7. Click Save Active Period.
  8. For the next campus, choose the next campus and the same term, then click Load Scope again.
  9. Do not load the standard 4-period set again unless the catalog is still missing or inactive. The catalog is shared for the tenant and term.
  10. Select that campus's active period and click Save Active Period. Repeat for the remaining campuses.
Simple rule: load the period catalog once per tenant and term. Save the active period once per campus and term.
How The Grading Controls Work Together
Step Setting What It Controls How Often To Set
1 Active Academic Scope The current Academic Year and Term used for normal faculty work. Once for the tenant when the school changes term.
2 Active Grading Period The current working period shown to faculty, such as Prelim or Midterm. Once per campus and term.
3 Period Locks The deadline and lock rule for a campus, term, and grading period. Once per campus and period, unless one class needs a special rule.
4 Grade Deadline Enforcement After the deadline, unsubmitted gradebooks require reopen approval before encoding or submission. Once per tenant policy, then review when workflow labels or monitoring practice changes.
5 Monitoring and Reopen Late submissions, non-compliance notices, and reopen requests after deadline or lock. Daily or as required during grading deadlines.
Example: For AY 2025-2026 / 2nd Semester, load the four period names once. Then save Fairview's active period, save Cubao's active period, and save Taytay's active period. After that, create Period Lock rows for each campus and period deadline.
Recommended NCBA starting point: Keep template drafting with the steward role. Use Dean or AC for review. Keep final approval, publishing, and hotfix final apply under CAO control.

7. Submission and Reopen Control

Set deadlines, monitor late submissions, and manage reopen requests.

Control Area Where To Apply What To Monitor / Action
Grading Period Locks Admin Portal -> Grading -> Period Locks Set the deadline, scope, and lock rule for a grading period.
Non-Compliance Monitor Admin Portal -> Grading -> Non-Compliance on Periodic Grades Submission See accepted faculty loads that are overdue and still unsubmitted.
Deadline Enforcement Policy Admin Portal -> Tools -> Configuration Management -> Grade Deadline Enforcement Enable automatic deadline closure or disable it when the institution intentionally wants unlocked gradebooks to remain open.
Grade Submission Status Admin Portal -> Grading -> Grade Submissions Check which class periods are open, submitted, reopened, or pending.
Reopen Governance Admin Portal -> Grading -> Grade Submissions plus Admin Portal -> Tools -> Correction Governance Use reopen only when there is an approved reason.
Deadline Automation Admin Portal -> Grading -> Period Locks and scheduled operations Run the scheduled job so deadline rules are applied on time.
Faculty Re-Submission Faculty Portal -> My Classes after admin reopen After an approved reopen request, faculty must finish and submit again within 24 hours.
How To Set Periodic Encoding Deadline Lock
  1. Open Grading -> Period Locks.
  2. Create a Period Lock row for the correct campus, term, and grading period. Example: Fairview / 2nd Semester / Prelim.
  3. Enter the deadline date and time.
  4. Use Scope Type: Campus when the same deadline applies to all classes in the campus.
  5. Use Scope Type: Course Offering only when one class needs a different rule.
  6. Turn on Is active. Inactive rules are ignored.
  7. Use Configuration Management -> Grade Deadline Enforcement to enable or disable automatic deadline closure.
  8. After the deadline or period lock, faculty must send a reopen request before encoding or submitting an unsubmitted gradebook.
  9. After the deadline, submitted/finalized gradebooks must use Correction of Grades. Do not use Gradebook Reopen Request for submitted gradebooks after deadline.
  10. After the deadline, monitor late rows in Non-Compliance on Periodic Grades Submission.
  11. Only users explicitly assigned reopen_requests.review by the Superadmin for the affected tenant/campus may review faculty reopen requests in Submission Reopen Requests. Once approved, the reopen window lasts 24 hours only.
  12. Keep the daily issue_submission_non_compliance_notices production cron active. TeacherMate+ sends up to three overdue notices only: faculty, then faculty plus Area Chair, then faculty plus Area Chair plus CAO.
Simple rule: Active Grading Period tells faculty which period is the current focus. Period Locks tell TeacherMate+ the deadline for each campus and period.
Submission, Reopen, and Correction Route
Situation Correct Route Admin Reminder
Before deadline, not yet submitted Faculty continues normal encoding and submits when ready. No reopen request is needed while the deadline has not passed.
Before deadline, already submitted Faculty may self-reopen, revise, and resubmit before the deadline. The action is audited.
After deadline, not yet submitted Faculty sends a Gradebook Reopen Request. If approved, faculty has 24 hours to finish and submit. If not submitted within 24 hours, the gradebook locks again and a new request is required.
After deadline, already submitted or finalized Use Correction of Grades only. No Gradebook Reopen Request. The correction must state exactly what needs to change, then follows approval, application, and audit.
After approved correction Only the approved correction scope may be changed. The correction window is time-limited and all actions are audited.
Clean distinction: Reopen Request is for unfinished or unsubmitted gradebooks after deadline or lock. Correction of Grades is for submitted or finalized gradebooks that need changes.
Reopening a Submitted Class Before Deadline
  1. Open Grade Submissions and filter by campus/term/course/section/period.
  2. Confirm the deadline has not passed. If the deadline already passed, use Correction of Grades instead.
  3. Click Reopen for the exact class-period row only when reopening is still allowed.
  4. Confirm the row status changes from SUBMITTED to open/reopened state.
  5. Inform faculty to revise and resubmit before the deadline.
Reopen applies to one exact class-period record only. Check the campus, term, course, section, period, and deadline before clicking.

8. Grade Correction Process

Use either online correction requests or the approved paper process.

Correction Path Where To Apply What To Do
System Request Mode Faculty Portal -> Grade Correction and the configured approval route Faculty files the request online. Approvers review it. Final approval updates the gradebook.
Official PDF Artifact Admin Portal -> Grade Correction Requests after approval Open the approved request as a PDF when the feature is enabled.
Approval Notifications Correction Governance and notification settings Email the current approver step and final faculty decision when correction notification is enabled.
Manual Only Mode Paper form + Admin Portal reopen path Use the paper route when required. After approval, an authorized admin reopens the exact class period.
System Request Mode
  1. Faculty files the correction request in the portal.
  2. If the faculty member is inactive or unavailable, an authorized admin can file the request on their behalf.
  3. Approvers review it based on the configured ordered route matrix and permissions, such as Area Chair -> CAO or Area Chair -> College Dean -> CAO.
  4. Faculty may include multiple students or the entire class plus multiple grading items in one request.
  5. Original values are shown in the request, and faculty enters only the corrected values.
  6. Final approval updates the gradebook and recomputes the affected grades.
  7. No extra faculty finalize step is needed for this direct correction flow.
  8. If enabled, approved requests can open as official PDFs for registrar or AIMS reference.
  9. If enabled, the system emails the current approver step and the final decision to the faculty requester.
Manual Only Mode
  1. Faculty files the paper correction form.
  2. Manual approvals are completed outside the system.
  3. After final paper approval, authorized admin reopens the class-period in TeacherMate+.
  4. Faculty applies the approved correction and re-submits grades.
Important Guardrails
  • The route matrix is based on the requesting faculty department.
  • CAO, dean, and coordinator users must have the correct scoped roles.
  • Use remarks and reference numbers for traceability, especially in manual mode.
  • All correction and reopen decisions are auditable.
  • Approved score correction values should be reviewed carefully because the final approval posts them directly into the gradebook and records before/after score, period-grade, and final-grade audit entries.
If the school requires paper as the official source, use MANUAL_ONLY. Faculty will not file the request online.

Admin Rules
  • Set the user's default tenant, campus, and department before giving access.
  • The normal Create User form intentionally omits Is staff. Assign portal access through scoped roles and permissions instead.
  • New-user emails use only the public TeacherMate+ root link. Give the Admin Portal URL separately only to authorized administrative users.
  • Give only the permissions the user needs.
  • Use the role-permission descriptions to understand what each permission group controls.
  • Use user_roles.update for assigning roles on user accounts. Use roles.update only for editing the role definition and its permission set.
  • For users who are both admin and faculty, give both portal permissions.
  • Use scheduled faculty deactivation when a faculty account should end later.
  • If email OTP is enabled, make sure the user's email is correct.
  • Forgot-password OTP is sent only to active users with Admin Portal access.
  • Recommended login lockout baseline: 5 failed attempts within 15 minutes, with a 15-minute lockout.

10. Faculty Assignment Acceptance

Make sure assigned classes are accepted by faculty or administratively confirmed by an authorized administrator before grading starts.

Workflow Summary
  • New assignments stay pending until the faculty responds or an authorized administrator confirms the assignment.
  • Pending assignments block grading and class-list work.
  • Faculty may accept, ask for clarification, or decline with a note.
  • Authorized administrative confirmation may place an assignment in Accepted without impersonating the faculty.
  • Pending assignments have a response deadline.
  • Expired assignments must be refreshed by admin.
Admin Procedure
  1. Open Faculty Assignments and select the faculty member.
  2. Use the colored headers to separate unassigned and assigned offerings.
  3. Filter by course or section before selecting offerings.
  4. Use Primary for the lead faculty and Secondary for shared-load faculty.
  5. Assign the offering and include instructions when needed.
  6. If needed, click Set Primary for the lead faculty load.
  7. Monitor the load status for Pending, Accepted, Clarification Requested, Declined, or Expired.
  8. Watch Accepted, Pending Acceptance, Due Within 24 Hours, and Expired counts.
  9. Review clarification or decline notes before editing or reissuing the assignment.
  10. If the assignment expired, refresh or reissue the load so a new response window is created.
Admin Rules
  • Do not treat a class as ready for grading until the assignment is accepted.
  • Use assignment instructions for schedule notes, room clarifications, or load-specific guidance.
  • Reissuing or changing the load should reset the response window so the latest version is accepted or administratively confirmed.
  • Follow up quickly on items marked Due Within 24 Hours.
  • Schedule manage.py process_faculty_assignment_reminders so reminders and expirations run automatically.
This workflow confirms the teaching load through faculty acceptance or authorized administrative confirmation before class work begins.

11. Audit and Monitoring

Use reports and logs to find issues early.

  • Use dashboards and reports to monitor submissions, failures, and exceptions.
  • Use audit logs to check important actions.
  • Use Recent Critical Actions for a quick review of resets, hotfixes, reopens, corrections, and critical permission changes.
  • Review correction/reopen actions before official release.
  • Use Faculty Activity Monitor to find faculty who have not logged in, created activities, or encoded grades.
  • Use Faculty Grade Book Monitor to review faculty gradebooks in read-only mode.
Faculty Activity Monitoring
  1. Open Faculty Activity Monitor from the Dashboard quick actions or from the Faculty Assignments page.
  2. Filter by campus, department, and term so AC and CAO review only the teaching loads they are responsible for.
  3. Choose the monitoring window, such as Last 7 Days or Current Term, to match the follow-up cycle you want.
  4. Review the summary cards first for No Login, No Activity Created, and No Grade Encoding counts.
  5. Use Window Activity Trend to see activity over time.
  6. Use the faculty table to spot who still has classes with No Activity Yet or No Scores Yet.
  7. Review the row-level flag badges to identify faculty who need follow-up for No Login, No Gradebook Update, or missing class maintenance.
  8. Open the optional faculty drilldown when you need the class-by-class view and recent auditable actions before contacting the faculty member.
  9. Use Week-over-Week Comparison to compare one faculty member's work across weeks.
  10. Use Print Report when you need a clean monitoring snapshot for meetings, weekly review, or compliance follow-up.
This monitor helps AC and CAO follow up before deadline issues become serious.
Faculty Grade Book Monitoring
  1. Open Faculty Assignments and select the faculty member within your allowed tenant, campus, and department scope.
  2. Use the acceptance status and metric cards to confirm whether the assigned load was accepted by faculty or administratively confirmed.
  3. Watch the Due Within 24 Hours and Expired metric cards so pending loads do not stall class opening and grading start-up.
  4. Review any assignment instructions, clarification requests, or decline notes directly on the assigned-offerings table before changing the load.
  5. Click Open Grade Book, then choose the accepted class and grading period to review. Pending, declined, clarification, or expired loads remain in Faculty Assignments but are not listed as reviewable gradebooks.
  6. Review the metric cards first for class coverage, averages, and pass rate before drilling into detailed rows.
  7. Use the student search box when you need to isolate a specific record during review.
  8. Grant gradebook.view_student_identity only to authorized reviewers who may verify student-level petitions or gradebook records using unmasked student numbers and names.
AC, Dean, and CAO review is read-only. Student identity stays masked unless the reviewer has permission.
Operations tip: schedule manage.py process_faculty_assignment_reminders so reminders and expirations run automatically.
Grade Prediction Monitor
How to Enable Grade Prediction and At-Risk Monitor
  1. Open Admin Portal -> Tools -> Configuration Management.
  2. Find the Grade Prediction card.
  3. Turn on Enable Grade Prediction.
  4. Select the roles that may use it. Include FACULTY so teachers can see prediction and at-risk tools in the Faculty Portal.
  5. Turn on the At-Risk Monitor option if faculty should see the Students At-Risk Monitor.
  6. Click Save.

If the link is still missing, check three items: Grade Prediction is enabled, the faculty role is selected, and the At-Risk Monitor option is enabled.
Student Academic Intervention Tracking
  • Enable this feature only through Configuration Management when the user has the explicit academic_interventions.configure permission.
  • Faculty analytics flags are recommendations for review, not automatic intervention requirements. The faculty owner records the professional decision.
  • Read-only monitoring requires academic_interventions.monitor plus valid assigned scope. Monitoring users cannot change a faculty decision, action, follow-up, close, or void a record.
  • Guidance does not receive intervention-record access by referral. Record only a controlled academic destination, optional approved-office label, date, and brief reason.
  • Prediction is unofficial and read-only. Enable it first in Configuration Management.
  • Open Grade Prediction Monitor to review projected outcomes for the scoped faculty, class, and period.
  • Use the monitor to spot low coverage, at-risk students, and likely current-period outcomes before submission deadlines.
  • Use Prelim for early warning, Midterm for intervention, Pre-Final for final follow-up, and Final for confirmation.
  • Faculty-side at-risk monitoring focuses on the active grading period when one is configured, while detailed final-grade projection remains available on the prediction detail page.
  • Prediction uses the same grading template path as the official computation engine, but it never writes to the gradebook.
  • Refresh the prediction snapshot after major score changes when you need an updated projection immediately.
Faculty Grade Distribution Monitor
  1. Grant authorized academic leaders the grade_distribution_monitor.read permission through Roles or direct user permissions.
  2. Open Configuration Management, then set the Faculty Grade Distribution Monitor thresholds for high-grade bands, exact 100 rates, low variation, and small sample size.
  3. Open Grade Distribution Monitor from the Admin Dashboard quick actions or the Grading menu.
  4. Filter by tenant scope, campus, department, academic year, term, faculty, and grading period as needed.
  5. Use Period Grades to review official stored period-grade distribution, or Activity Scores to review encoded activity-score patterns.
  6. Review the neutral status badges: High Grade Concentration, High Perfect Score Rate, Low Grade Variation, Small Sample, Incomplete Data, and No template.
  7. If the monitor warns that a class has no published grading template, fix the course-template assignment before relying on period filters or template-based interpretation.
  8. Use Export CSV when a meeting or review needs an aggregated copy of the scoped results.
This monitor is read-only and uses aggregated data by default. It is intended for academic review and informed follow-up, not automatic disciplinary action.
Submission Non-Compliance Notices
  1. Open Configuration Management, then find the Submission Non-Compliance Notices card.
  2. Enable the feature after SMTP/email settings are confirmed.
  3. Keep Scheduler cadence as the daily overdue-gradebook check. It controls how often the command checks; it does not directly set the escalation day.
  4. Use First notice after deadline, Notice interval, and Maximum notices to control the notice schedule. Defaults are 1, 1, and 3, which means Notice 1 on Day 1, Notice 2 on Day 2, and Notice 3 on Day 3.
  5. Make sure Area Chair and CAO users have the correct scoped role assignments. TeacherMate+ uses those assignments to decide who receives the second and third notices.
  6. Open the Non-Compliance on Periodic Grades Submission report to monitor overdue unsubmitted classes and review the latest notice stage and issue date.
  7. With the NCBA defaults, day 1 after the deadline goes to the faculty only; day 2 goes to faculty plus Area Chair; day 3 goes to faculty plus Area Chair plus CAO.
  8. TeacherMate+ stops automatic overdue notices after the configured maximum notice count. The Area Chair and CAO handle follow-up after that point.
Best practice is to run the notice scheduler daily. TeacherMate+ checks the deadline age and only issues the next communication when that stage is due.
Early readiness email command: manage.py send_submission_readiness_alerts (daily at 1:00 AM Asia/Manila; disabled by default). Configure the days, strict below-threshold percentage, and scoped Area Chair/Dean/CAO recipients under Configuration Management.
Scheduled job command: manage.py issue_submission_non_compliance_notices
Optional dry run: manage.py issue_submission_non_compliance_notices --dry-run
Optional tenant scope: manage.py issue_submission_non_compliance_notices --tenant-id 1
Operations tip: schedule this command as a daily background task on the application server after SMTP/email settings are confirmed. The command only issues read-only communications and does not lock classes or change any grade records.

12. End-of-Term Checklist

Check all submissions, corrections, and clearance before closing the term.

  • Confirm active AY/Term and role scopes.
  • Confirm all lock/deadline configurations are correct.
  • Track and resolve non-submitted classes.
  • Process correction/reopen according to chosen policy mode.
  • Open Faculty Final Clearance after final submissions are complete.
  • Open Academics -> Course Offerings and use Complete Tabulation to generate the same detailed Legal landscape activity-and-grade PDF available to the Faculty of Record. The copy uses the faculty signature when enabled and available, never the generating Admin's signature.
  • Verify printed clearance using the QR code or the Reference No. and Verification Code.
  • Use Configuration Management -> User Signatures to control where stored signatures may appear.
  • Correction attachments and official reports open only through authenticated TeacherMate+ views and are audited.
  • Review audit logs and analytics before final release/export.

14. Production Incident Response

Collect facts first, then stabilize the system.

Incident Step What To Do Where To Apply / Check
1. Capture Evidence Get the URL, time, screenshot, affected user/role, and last action before the error. Browser error page, user report, and server timestamp reference.
2. Confirm Scope Check if the issue affects one page, one portal, one campus, or many users. Admin and Faculty login pages, dashboard pages, and one affected workflow page.
3. Freeze Risky Changes Do not make random fixes while the cause is still unknown. Operational response discipline during live incident handling.
4. Check Server Health Check application logs, server logs, disk space, and recent releases. Production server logs and the Ubuntu deployment environment.
5. Decide Recovery Path Rollback if a new release caused the issue. Use a hotfix only when the cause is clear. Release history, recent deployment notes, and current impact scope.
6. Escalate with Evidence Send the traceback, screenshot, URL, affected user/role, and recent change details. docs/PRODUCTION_INCIDENT_RUNBOOK.md and incident support coordination.
Where To Apply
  1. Use the detailed production response guide in docs/PRODUCTION_INCIDENT_RUNBOOK.md for command-level triage and rollback/hotfix decisions.
  2. Use Admin Portal -> Security -> Login Lockouts if login failures or account lockouts are part of the incident.
  3. Use Admin Portal -> Audit Logs and governance pages when the incident involves template, correction, reopen, or scope-setting changes.
  4. Use the production deployment guide in docs/DEPLOYMENT_UBUNTU.md for service restart and release-update procedures.
Practical rule: save evidence first, stabilize second, and deploy a fix only after the cause is clear.
