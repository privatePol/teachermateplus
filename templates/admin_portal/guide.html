1. Quick Start Sequence

Phase A - Foundation Setup
  1. Set top scope first: Tenant then Campus.
  2. Verify academic setup: AY/Term, Course, Section, Offering, Faculty Assignment.
  3. Set active AY/Term for faculty active/archive behavior.
Phase B - Governance Controls
  1. Configure grading deadlines and lock rules.
  2. Set correction governance mode and route matrix.
Phase C - Operations Monitoring
  1. Monitor submissions, reopen actions, and correction queue.
  2. Run audit checks before official release/export.
Recommended sequence each term: Scope -> Setup -> Governance -> Monitoring. Avoid doing reopen/correction actions until deadline rules and correction mode are already configured.

2. Scope Selectors (Tenant/Campus)

  • Tenant/Campus selectors define operational scope for most list/create/edit actions.
  • Wrong scope selection causes missing/incorrect records in view.
  • Always verify scope before import, reopening, and policy updates.
How To
  1. Select tenant first, then select campus.
  2. Open target module and verify listed records align with selected scope.
  3. If data looks wrong, check selectors first before deeper troubleshooting.

3. Configuration Setup

  • Create Tenant and Campuses.
  • Create Departments and Programs.
  • Create Academic Years and Terms.
  • Create Courses and Sections.
  • Create Course Offerings and Faculty Assignments.
  • Proceed to Enrollment and grading setup.
How To
  1. Follow strict order: Tenant -> Campus -> Department/Program -> AY/Term.
  2. Create course/section masters, then offerings and faculty assignments.
  3. Verify all references are active before import/operations.

4. Records Management

  • Use filters before editing records.
  • Prefer inactivation for historical traceability.
  • Keep codes consistent across imports and operations.
  • Review related dependencies before major edits.
How To
  1. Filter -> Edit exact record -> Save -> Re-verify in list.
  2. Inactivate records instead of deleting when operations already depend on them.
Data quality is the top source of grading stability.

5. Governance Settings

  • Set Active AY/Term for academic scope governance.
  • Set Correction Governance Mode: SYSTEM_REQUEST or MANUAL_ONLY.
  • Set pre-deadline behavior (when SYSTEM_REQUEST is used).
  • Set route matrix by requesting faculty department.
  • Set document print header values.
  • Use Configurable Features for optional workflow toggles such as correction official report generation and registrar auto-email settings.
How To
  1. Go to Tools and open each settings screen by scope.
  2. Save mode/settings then verify behavior in Faculty summary and corrections screens.
  3. Limit update permissions to authorized governance roles only.

6. Tools and CSV Importing

  • Use only system-generated templates.
  • Upload and validate first; no insert should occur yet.
  • Review row-level errors and duplicates.
  • Confirm import only after all validation issues are resolved.
How To
  1. Download template for specific import type.
  2. Populate required fields with valid business keys.
  3. Upload CSV -> review validation result.
  4. Fix source data and re-upload until valid.
  5. Confirm import and verify list pages.
Strict headers are required by design; custom formats are rejected.

7. Submission and Reopen Control

  • Configure deadlines and locks in Grading Period Locks.
  • Monitor submission status in Grade Submissions.
  • Use reopen controls only with approved governance and role permissions.
  • Deadline-driven locks should be backed by scheduled auto-lock job.
How To
  1. Create period lock rule and deadline by scope.
  2. Track pending submissions near deadlines.
  3. For approved reopen, process from Grade Submissions (authorized user only).
  4. Ensure faculty re-submits after correction.
Reopening a Submitted Class (Admin Procedure)
  1. Open Grade Submissions and filter by campus/term/course/section/period.
  2. Confirm approved basis (system request approval or manual signed form).
  3. Click Reopen for the exact class-period row.
  4. Confirm the row status changes from SUBMITTED to open/reopened state.
  5. Inform faculty to apply corrections and re-submit before deadline.
Reopen always applies to the class-period submission record, so admins must verify the exact course-section-period before clicking.

8. Correction Workflow (System vs Manual)

SYSTEM_REQUEST Mode
  1. Faculty files correction request in portal.
  2. Approvers review based on route matrix and permissions.
  3. Faculty may include multiple students or the entire class plus multiple grading items in one request.
  4. Original values are shown in the request, and faculty enters only corrected values.
  5. Final approval applies the corrected values directly into the gradebook and recomputes the submitted period automatically.
  6. If the configurable feature is enabled, approved requests can also be opened as an official PDF artifact in a new browser tab for registrar/AIMS reference and immediate print/download, including campus applicability, before/after official grade values, and approval summary directly above registrar reference.
  7. If the configurable feature is enabled, submission of a correction request can immediately email the selected approver roles such as CAO and college dean, using the NCBA-branded notification card with petitioner and period name details.
MANUAL_ONLY Mode
  1. Faculty files paper correction form.
  2. Manual approvals are completed outside system.
  3. After final paper approval, authorized admin reopens class-period in EduGradesPro.
  4. Faculty applies approved correction and re-submits grades.
Important Guardrails
  • Route matrix is based on requesting faculty department.
  • CAO/dean/coordinator users must have correct scoped roles.
  • Use remarks/reference number for traceability, especially in manual mode.
  • All correction/reopen decisions are auditable.
  • Approved score correction values should be reviewed carefully because the final approval posts them directly into the gradebook.
If registrar policy requires paper source-of-truth, set mode to MANUAL_ONLY. Faculty does not file online request; admin executes reopen only after approved form.

9. Security and User Administration

  • Enforce domain policy, password complexity, first-login password change, and privacy consent.
  • Assign default tenant/campus/department correctly per user.
  • Grant least privilege and role scopes carefully. Role assignments can now be scoped by tenant, campus, and department for AC/Dean governance boundaries.
  • For dual-role users (admin + faculty), ensure both portal permissions are assigned.

10. Faculty Assignment Acceptance and Monitoring

Workflow Summary
  • Newly assigned classes remain pending until the faculty member acknowledges the load.
  • Pending assignments block access to grading and class-list work.
  • Faculty may accept, request clarification, or decline with a written note.
  • Pending assignments carry a response deadline and may expire if left unanswered.
  • Expired assignments require admin refresh before the faculty member can respond again.
Admin Procedure
  1. Open Faculty Assignments and select the faculty member.
  2. Assign the offering and include instructions when needed.
  3. Monitor the load status for Pending, Accepted, Clarification Requested, Declined, or Expired.
  4. Use the metric cards to watch Accepted, Pending Acceptance, Due Within 24 Hours, and Expired.
  5. Review clarification or decline notes before editing or reissuing the assignment.
  6. If the assignment expired, refresh or reissue the load so a new response window is created.
Admin Rules
  • Do not treat a class as ready for grading until the assignment is accepted.
  • Use assignment instructions for schedule notes, room clarifications, or load-specific guidance.
  • Reissuing or changing the load should reset the acknowledgment window so the faculty confirms the latest version.
  • Follow up quickly on items marked Due Within 24 Hours.
  • Schedule manage.py process_faculty_assignment_reminders so reminders and expirations run automatically.
This workflow creates a formal checkpoint between load assignment and grading access, helping protect both faculty accountability and class-start readiness.

11. Audit and Monitoring

  • Use dashboard and analytics to monitor submissions, failures, and exceptions.
  • Use audit logs for policy-critical actions and decision traceability.
  • Review correction/reopen actions before official release.
  • Use Faculty Grade Book Monitor for read-only academic oversight of a scoped faculty member's classes and period grades.
Faculty Grade Book Monitoring
  1. Open Faculty Assignments and select the faculty member within your allowed tenant, campus, and department scope.
  2. Use the acceptance status and metric cards to confirm whether the faculty member already acknowledged the assigned load.
  3. Watch the Due Within 24 Hours and Expired metric cards so pending loads do not stall class opening and grading start-up.
  4. Review any assignment instructions, clarification requests, or decline notes directly on the assigned-offerings table before changing the load.
  5. Click Open Grade Book, then choose the class and grading period to review.
  6. Review the metric cards first for class coverage, averages, and pass rate before drilling into detailed rows.
  7. Use the student search box when you need to isolate a specific record during review.
AC, Dean, and CAO monitoring opens the grade book in read-only mode. Student identity can be masked by role, and every monitor open is recorded in the audit trail.
Operations tip: schedule manage.py process_faculty_assignment_reminders in cron so pending loads are reminded automatically and overdue loads are marked expired without waiting for a user to open the page.
Grade Prediction Monitor
  • Prediction is unofficial and read-only. It must be enabled first in Configurable Features.
  • Open Grade Prediction Monitor to review projected outcomes for the scoped faculty, class, and period.
  • Use the monitor to spot low coverage, at-risk students, and likely grade outcomes before submission deadlines.
  • Prediction uses the same grading template path as the official computation engine, but it never writes to the gradebook.
  • Refresh the prediction snapshot after major score changes when you need an updated projection immediately.

12. End-of-Term Checklist

  • Confirm active AY/Term and role scopes.
  • Confirm all lock/deadline configurations are correct.
  • Track and resolve non-submitted classes.
  • Process correction/reopen according to chosen policy mode.
  • Review audit logs and analytics before final release/export.

13. Policy and Governance Reference

Policy Area Operational Rule
Scope and Access All operations must respect tenant/campus scope and assigned permissions.
Submission Governance Submission and reopen decisions must follow configured deadlines and authorized roles.
Correction Governance Use SYSTEM_REQUEST or MANUAL_ONLY according to institutional policy.
Import Controls Only official templates with strict headers are accepted.
Auditability Critical actions must remain reviewable via audit logs.
Privacy Data handling must comply with institutional privacy policy and role boundaries.
